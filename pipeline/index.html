    Image-text similarity Pipeline

    Image‑text Similarity Pipeline

    This project provides two optimized pipeline implementations for computing image‑text similarity scores:

    • ImageTextPipeline (Single‑Node, Async)
    • RayImageTextPipeline (Distributed, Ray)

    Both share the same high‑level steps—CSV chunking, image download & cache, batched model scoring, metrics logging, and result output but differ in concurrency and resource distribution.

    Common Workflow

    1. Configuration Load

    • Uses config_loader.load_config() to read & validate the base config conf/config.yaml as well as the metric specific config conf/model/*.yaml + the CLI overrides.

    2. Component Initialization

    • CSV Reader: ChunkedCSVReader for streaming large files.
    • Cache Manager: CacheManager with TTL based on app.cache_dir & app.ttl_days.
    • Model: Created via ModelFactory.create_model(config.model).
    • Logger & Metrics: setup_logger + MetricsLogger to track throughput, errors, GPU usage, and score distributions.
    • CSV Writer: CSVWriter outputs to output.path with dynamic ${model.type} replacement.

    3. Process Loop

    Iterate over CSV chunks → split into batches → download/cache images → load & validate → score via model → record & write results.

    Cleanup

    Close cache, writer; write metrics JSON & score distribution plot; flush logs.

    ImageTextPipeline

    Use The Async, Single‑Node Version when you need a simple setup on one machine. Ideal for development, experimentation, or small‑scale runs.

    Key Features

    • Async I/O: Uses asyncio + AsyncHTTPClient for concurrent downloads.
    • Batch Inference: Groups records into batches (config.model.batch_size) for efficient GPU usage.
    • Chunked Reading: Prevents OOM when loading very large CSVs.
    • Smart Caching: TTL‑based caching to avoid re‑downloads.
    • Robust Error Handling: Continues past failed downloads or corrupt images, logs counts.

    High‑Level Flow

    1. Initialization

    pipeline = ImageTextPipeline(config)

    2. Run

    asyncio.run(pipeline.run())

    3. Per-chunk

    • Download missing images (_precache_images)
    • Load images with thread‑pool (_load_images)
    • Validate & filter (_validate_images)
    • Score batch (_score_valid_records)
    • Write rows & update metrics (_format_batch_results)

    4. Finalize

    cache.close(), writer.close(), metrics_logger.write_summary(), metrics_logger.save_score_distribution_plot()

    RayImageTextPipeline

    Use The Distributed Ray Version for large‑scale, multi‑GPU/-node runs—ideal for processing tens to hundreds of millions of records in parallel.

    Additional Features

    • Ray Tasks: Spawns app.ray_workers RayWorker actors, each with its own model instance.
    • Multi‑GPU Support: Distributes across app.num_gpus GPUs (one GPU per worker by default).
    • Optional Index Mode: If cache_dir/annoy_indices/ contains index data, switches to nearest‑neighbor lookups without any model inference.

    🌐 Key Differences from Base Pipeline

    Feature Base Pipeline Ray Pipeline
    Processing Single-process async Distributed across workers
    Model Instances Single One per worker
    Resource Use Single GPU/CPU Cross-device/cluster
    Pre computed embeddings support No Yes

    High‑Level Flow

    1. Initialization

    pipeline = RayImageTextPipeline(config)
pipeline.run()

    2. Ray Setup

    • ray.init(num_gpus=config.app.num_gpus)
    • Create app.num_gpus workers via @ray.remote(num_gpus=1)

    3. Processing

    For each CSV chunk:

    • Split into batches
    • Dispatch worker.score_batch.remote(batch)
    • ray.get() to collect results
    • Write & log via CSVWriter and MetricsLogger

    4. Annoy Index Integration (optional)

    Index Mode Detection

    Pipeline switches to index mode when detects:

    • Annoy index file (.ann)
    • Embedding numpy array (.npy)
    • Metadata mapping (.jsonl)
      cache_dir/
  ├── annoy_indices/
  │   ├── clip_index.ann       # Binary index file
  │   └── clip_meta.jsonl      # URL-to-embedding ID mapping
  └── embeddings/
      └── clip_embs.npy        # Combined image-text embeddings

    If found, score_batch uses _score_with_inde; else _score_with_inference.

    Configuration Hooks

    • Batch Size: config.model.batch_size controls number of examples per GPU inference call.
    • Concurrency:
    • Single‑node: config.app.max_connections for HTTP client concurrency.
    • Ray: config.app.ray_workers and config.app.num_gpus.
    • Index Mode: Drop an Annoy index + embeddings into your cache_dir to bypass inference.
    • QA Models: The TIFA pipeline outputs extra columns (questions, correct_answers, model_answers) when model.type=tifa, handled automatically.

    Examples

    Single‑node CLIP, no Ray

    python src/pipeline.py --model clip --app.use_ray=False

    Single‑node with 4 GPUs

    python src/pipeline3.py --model clip --app.num_gpus=4

    Distributed ImageReward on 4 GPUs and 4 Ray workers

    python src/pipeline3.py \ --model image_reward \ --app.use_ray=True \ --app.num_gpus=4 \ --app.ray_workers=4
